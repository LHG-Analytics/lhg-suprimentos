### `middleware.ts`

```ts
import { NextResponse, type NextRequest } from 'next/server';
import { createServerClient } from '@supabase/ssr';

const ROUTE_ROLES: Record<string, string[]> = {
  '/config': ['admin'],
};

export async function middleware(req: NextRequest) {
  const res = NextResponse.next();
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    { cookies: { get: (n) => req.cookies.get(n)?.value, set: (n, v, o) => res.cookies.set(n, v, o), remove: (n, o) => res.cookies.delete(n) } }
  );
  const { data: { user } } = await supabase.auth.getUser();

  const path = req.nextUrl.pathname;
  const isPublic = path.startsWith('/login') || path.startsWith('/auth');

  if (!user && !isPublic) {
    return NextResponse.redirect(new URL('/login', req.url));
  }
  if (user && path === '/login') {
    return NextResponse.redirect(new URL('/dashboard', req.url));
  }

  // Role check for guarded routes
  const guarded = Object.keys(ROUTE_ROLES).find((p) => path.startsWith(p));
  if (guarded && user) {
    const { data: profile } = await supabase.from('user_profiles').select('role').eq('id', user.id).single();
    if (!ROUTE_ROLES[guarded].includes(profile?.role ?? '')) {
      return NextResponse.redirect(new URL('/dashboard', req.url));
    }
  }

  return res;
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)'],
};
```

## 6. Server Actions vs Route Handlers

| Caso | Use |
|---|---|
| Form submission, mutação simples ligada a UI | **Server Action** |
| Endpoint público / webhook / cron / chamada de terceiros | **Route Handler** |
| Streaming (chat IA) | **Route Handler** com `Response` stream |
| Operação multi-passo com transação | Server Action que chama RPC do Postgres |

## 7. Padrões a seguir

- **Always** use Server Components para data fetching. Client Components apenas para interatividade.
- **Always** valide inputs com Zod (`'use server'` actions sempre fazem parse).
- **Always** use `revalidatePath` ou `revalidateTag` após mutações para invalidar caches.
- **Never** chame `service-role` Supabase client direto de Client Components.
- **Never** confie em filtros do client — RLS é a verdade.
- **Always** loggue erros de integração (Omie, Resend) em `audit_log` + Sentry.

## 8. Testes recomendados

- **Unit:** funções puras (format, RAG context builder, NFe parser) com Vitest.
- **Integration:** fluxo Requisição → Cotação → Pedido → NF com Supabase test DB.
- **E2E:** Playwright cobrindo: login, criar requisição, gerar cotação, aprovar pedido, lançar NF.
- **RLS:** testes específicos validando que cada role só vê o que pode.

## 9. Deploy

- **App:** Vercel (Next.js 16 nativo)
- **DB:** Supabase managed
- **Storage:** Supabase Storage
- **Cron:** Vercel Cron (`vercel.json`) ou Supabase Edge Functions com pg_cron
- **Monitoramento:** Sentry + Vercel Analytics + Logflare/Grafana pro Supabase
